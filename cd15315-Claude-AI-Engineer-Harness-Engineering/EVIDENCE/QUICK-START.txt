## 4. For Each System: Build → Run → Capture

  a) Build the system
     cd <project>/<exercise>/solution
     python -m venv .venv && source .venv/bin/activate
     pip install -e ".[dev]"

  b) Run tests
     pytest tests/ -v
     → Save output to: EVIDENCE/system-N-*/pytest-run.txt

  c) Run the system end-to-end
     (Follow instructions in system README)
     → Save artifacts to: EVIDENCE/system-N-*/runs/

  d) Analyze the code and artifacts
     → Write markdown files in: EVIDENCE/system-N-*/<matching-structure>/

## 5. Three Types of Files You'll Create

  TYPE 1: Artifact Captures (raw, unedited)
    - pytest-run.txt (terminal output)
    - *.json (actual JSON files)
    - *.jsonl (trace/event files)
    Pattern: <run-name>.txt, *.json, *.jsonl

  TYPE 2: Analysis Documents (your interpretation)
    - *-analysis.md (parse and explain artifacts)
    - *-overview.md (explain what code does)
    - README.md (explain tier or layer)
    Pattern: *-analysis.md, *-overview.md

  TYPE 3: Test Summaries (parsed pytest)
    - pytest-run-summary.md (test count, failures)
    - test-*.md (explain what each test module verifies)
    Pattern: pytest-run-summary.md, test-*.md

## 6. Citation Pattern for Reflection Brief

TEMPLATE:
  "From EVIDENCE/system-N-*/<path>/<file>.md, [fact]. Quote from project <file.py>:<line>."

EXAMPLE 1 (System 1):
  "From EVIDENCE/system-1-claims-intake/runs/traces/claim-01-trace.md, the stop_reason
  sequence is: tool_use, tool_use, end_turn. The loop decision logic is in
  claims_intake/loop.py:42 where it checks 'if response.stop_reason == end_turn: break'."

EXAMPLE 2 (System 3):
  "From EVIDENCE/system-3-claude-config/.claude/skills/deploy-check/skill-context-fork.md,
  the skill has 'context: fork' (SKILL.md line 4). This keeps verbose discovery output
  isolated from the main session."
